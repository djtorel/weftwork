## Method

Accessed 2026-11-10. I ran no workflow and no measurement: no hook trial, no gate trial, no override count across repositories, no token count, and no test of whether any hook in this repository blocks a call (owner decision, 2026-11-10). This brief reads papers and documentation only. Each check it needs is listed under Open questions as a candidate for R10.

Versions read. Installed here: pi 1.5.0, Claude Code 2.1.321, codex-cli 0.167.0 and opencode 1.19.5 (`--version` output on 2026-11-10). Kiro is closed source and not installed; I read its pages as served on 2026-11-10 and record each page's own "Page updated" date in Sources. I read the Claude Code and Codex pages as served on 2026-11-10, the opencode pages at tag v1.19.5, and the pi page as a raw file from `main` at commit 473515f9c297, which may be ahead of the installed version. Commit ids come from `git ls-remote` over https.

I fetched every doc page, vendor post and Kiro page myself with `curl` or a short Python fetch script, and stripped the HTML tags with my own script. I used no `gh api` and no `api.github.com`. No page came through a summarizing subagent, and I started no subagent. The Kiro steering and hooks pages that R3 read only through a summary I read directly: the steering page for scope, inclusion modes, foundation files and the custom-agent note (not its best-practices and example sections), and the hooks, hook-types and hook-actions pages for the passages on event triggers, the Pre Tool Use exit-code behaviour, default timeouts, and which surfaces run them. I read the Claude Code hooks and permissions pages by searching them for exit-code, failure, blocking, disable, bypass and rule-order terms and reading the matching passages, not end to end; the Codex, pi and opencode pages the same way.

I read the papers' abstracts through the arXiv Atom API over https (`export.arxiv.org`) and the arxiv.org abstract pages, two to five seconds apart. For the papers whose numbers carry weight in the verdicts (S1, S2, S4, S5, S6, S8, S10, S11, S17) I also downloaded the HTML full text and read the passages on setup, evaluation protocol, results and limitations; I did not read those texts end to end. The claims taken from the other papers (S3, S7, S9, S12 to S16, S18 to S23) rest on abstracts and are marked as abstract-level. Dates in Sources are the first-version dates the arXiv API gives; for S2, S11 and S13 the id month is later than that date, and I kept the API date.

arXiv queries, in order (field `all:` unless noted, sorted by relevance, six or seven results each; I did not control `OR` and `AND` precedence): (1) title search `ti:"Code as Agent Harness"`; (2) `Code as Agent Harness survey`; (3) `agent harness code execution survey`; (4) `runtime enforcement LLM agent tool calls policy`; (5) `coding agent guardrails permission enforcement`; (6) `agent instruction files compliance executable constraints`; (7) `coding agents follow AGENTS.md rules compliance`; (8) `risk-adaptive verification coding agent`; (9) `approval fatigue permission prompts coding agent`; (10) `LLM judge versus deterministic test verification coding agent`; (11) `self-reported completion agent claims done without verification`; (12) `agent harness hooks lifecycle enforcement`; (13) `coding agent bypasses tests modifies tests reward hacking`; (14) `tiered verification effort proportional to change risk software agents`; (15) `security warning habituation override rate developers`; (16) `agent disables guardrail circumvents safety check coding agent`; (17) `pre-commit hooks CI gates developers bypass`; (18) `risk-based testing`; (19) `alert fatigue developers static analysis warnings ignored`; (20) `agentic pull requests review effort risk`; (21) `coding agent harness adaptive ceremony task difficulty`; (22) `rules versus prompts enforcement LLM agent compliance benchmark`; (23) `portable agent configuration across coding agents Claude Code Codex Cursor`; (24) `agent skills SKILL.md ecosystem empirical`; (25) `empirical study risk-based testing effectiveness`; (26) `multiple coding agents same repository shared state coordination files`.
